Project: POS App ERP QA Automation
Stack: Python, pytest, pytest-playwright, Playwright, POM, Playwriter, Claude Code

## Structure
- `pages/<module>/*_page.py` — one page object per screen (e.g. `pages/purchase/purchase_order_page.py`). `pages/login_page.py` is the only top-level exception.
- `tests/<module>/test_*.py` — one spec per feature, mirrors `pages/` layout.
- `utils/*_config.py` — test-data builder functions (e.g. `get_local_purchase_order_data()`), imported by specs.
- `test_data/` — loads `test_data/<dev|prod>/master_data.py` based on `CONFIG["env"]`, exposes shared `test_data` (office, customer, employee, supplier, item, ...).
- `config/app_config.py` — env-aware `CONFIG` dict (baseURL, username, password) via `ENV=dev|prod`.
- `auth/<env>-user.json` — storage_state, generated by the session-scoped `authenticate` fixture in `conftest.py`. Gitignored, not committed.
- `test-cases/<feature>/` — manual test case docs/CSVs, not automation.
- `dashboard/` — local web console (FastAPI backend + React/Vite frontend) for manually picking and running test cases from the browser via live `pytest` execution. Separate tooling, not part of the test suite itself; never wired into `pytest.ini`/`conftest.py`. Run with `pip install -r dashboard/requirements.txt && python -m uvicorn dashboard.backend.main:app --port 8000`, then `cd dashboard/frontend && npm install && npm run dev`.

## Rules
- Act as a Senior SDET/QA Agent for an ERP product.
- Reuse existing page objects, utils, and test-data — never duplicate an existing method or config builder.
- One page object per screen; one spec per feature; follow existing file/folder naming.
- Use existing `auth/<env>-user.json` storage_state (wired via `conftest.py`'s session-scoped fixtures). Do not touch the `authenticate` fixture in `conftest.py` or automate login unless explicitly requested.
- Inspect the UI with Playwriter before creating or changing locators.
- Locator priority: `get_by_role` / `get_by_label` / `get_by_test_id` / `get_by_placeholder` > stable CSS. Avoid XPath.
- Match existing locator conventions per screen (e.g. PurchaseOrderPage's react-select helpers) instead of introducing new patterns for the same UI kit.
- Avoid `time.sleep`; use Playwright's built-in waits/assertions. (The Turnstile poll loop in `login_page.py` is an intentional, documented exception — don't copy it elsewhere.) A slower save/submit can get its own `expect(...).to_be_visible(timeout=...)` override instead (see `test_login.py`'s 20s post-login wait) — don't raise the global 5s default in `conftest.py` for one slow screen.
- Keep methods small, reusable, readable; add meaningful `expect` assertions (e.g. success notifications, row visibility).
- Generate test data only through `utils/*_config.py` + `test_data/`; don't inline literals that belong there. Random data (names, ids, passwords, etc.) must actually satisfy the app's own validation (e.g. password strength) — check the real UI behavior, don't assume a placeholder value like "123456" is accepted.
- Screenshots/video/trace: rely on existing `pytest.ini` settings — don't override per-test.
- Do not modify unrelated files.
- Before coding, inspect existing implementation and reuse it.
- For ERP workflows, consider cross-module dependencies (Purchase, Sales, Inventory, Accounting, HR, etc.).
- Never perform destructive or production-impacting actions without explicit approval.
- Do not bypass CAPTCHA, Cloudflare Turnstile, MFA, authentication, or other security controls.
- On test failure: inspect error, screenshot, trace, console/network evidence, then diagnose root cause before fixing — a red result can come from real app validation (e.g. a rejected password), not just a bad locator or timeout.
- After implementation, report changed files and test results.
